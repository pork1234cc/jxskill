# 小红书关键词采集规范 v0.4

## 1. 职责

`xiaohongshu-collector` 负责：

```text
读取即时参数或飞书未采集任务
→ 搜索并限制卡片数量
→ 使用搜索卡片筛选
→ 请求合格笔记详情
→ 保存本地素材
→ 写入飞书
```

不负责内容质量、爆款原因、选题价值、写作、配图或发布。

## 2. 两种执行入口

### 2.1 即时采集

用户直接提供一个关键词和采集数量。飞书配置完整时新建一条任务记录；否则只保存本地结果。

```powershell
python .agents/skills/xiaohongshu-collector/scripts/run_collector.py collect "AI工具" --count 5
```

### 2.2 任务表采集

用户说“开始笔记采集”时，读取采集任务表中全部 `采集状态 = 未采集` 的记录，按飞书返回顺序逐条执行。

```powershell
python .agents/skills/xiaohongshu-collector/scripts/run_collector.py tasks
```

任务表模式领取已有记录并更新状态，不新建重复任务。

## 3. 参数模型

```yaml
keyword: AI工具
collect_count: 40
note_type: all
time_filter: 不限
min_likes: 100
min_collects: 100
min_comments: 20
sort: general
```

`collect_count` 是每个关键词最多读取的搜索卡片数。它不是合格笔记目标数，也不存在另一个 `max_scan`。

即时采集默认读取 40 条；明确指定数量时以用户输入为准。任务表模式读取“采集数量”字段，并对拆分后的每个关键词分别应用。

## 4. 固定选项

发布时间：

```text
不限
一天内
一周内
半年内
```

发布时间由搜索接口执行，不计算 3 天、30 天或 90 天，也不在详情阶段复筛。

笔记类型：

```text
不限 → all
图文 → image
视频 → video
```

排序依据：

```text
综合       → general
最新       → latest
最多点赞   → likes
最多评论   → comments
最多收藏   → collects
```

## 5. 多关键词

任务表“搜索关键词”字段支持半角 `#`：

```text
AI工具# AI编程 ##AI工具
```

解析为：

```text
AI工具
AI编程
```

规则是去除首尾空格、忽略空词、保持首次出现顺序并去重。每个关键词独立读取“采集数量”指定的卡片数。

## 6. 搜索卡片 Gate

搜索卡片已经提供 Note ID、笔记类型、点赞、收藏和评论，因此这些字段在发起详情请求前完成判断；最终保存的点赞、收藏和评论也以搜索卡片值为准。

三个互动阈值固定使用 `ALL`：

```text
点赞 >= min_likes
AND 收藏 >= min_collects
AND 评论 >= min_comments
```

只有大于 0 的阈值参与；`0` 或空值表示关闭。启用字段缺失时直接跳过该卡片，不为了补筛选字段请求详情。

发布时间作为 `time_filter` 直接传给搜索接口。类型字段存在时按 `note_type` 判断；限定类型但搜索卡片缺失类型时跳过。

## 7. 详情和素材

搜索 Gate 通过后才请求详情。详情只用于补充：

- 完整正文；
- 作者昵称和用户 ID；
- 话题；
- 原文链接；
- 图片或视频地址。

详情阶段不按互动数或发布时间再次淘汰。详情响应无合法 Note ID、请求失败或数据无法解析时，该笔记记录为异常且不进入正式结果。

评论数只使用搜索卡片字段完成门槛筛选。当前不请求评论接口、不保存评论正文，也不写飞书评论表。

图文笔记下载图片，视频笔记下载视频。素材下载失败不重新请求 TikHub，但会使任务成为“部分成功”。

## 8. 停止条件

唯一正常停止条件是：

```text
scanned_cards >= collect_count
```

搜索结果耗尽时也停止。合格笔记数量不会触发提前停止，也不会驱动继续翻页。

例如：

```text
采集数量：40
搜索卡片：40
通过 Gate：13
详情成功：12
最终保存：12
```

任务已经完整执行，不会继续搜索以凑够 40 篇。

## 9. 任务内去重

每张搜索卡片都计入 `collect_count`；同一关键词出现重复 Note ID 或缺失 Note ID 时，只计入卡片数并跳过详情。一个飞书任务包含多个关键词时，共用任务级 Note ID 缓存：

- 后续关键词再次命中已采集 Note ID，不重复请求详情；
- 飞书笔记只写一次；
- “来源关键词”按首次命中顺序合并。

不同任务再次命中同一 Note ID 时，飞书更新互动数据和来源关键词，并保留首次任务 ID。

## 10. 飞书任务状态

状态流转：

```text
未采集 → 采集中 → 成功 / 部分成功 / 失败
```

- 成功：全部关键词完成，包括最终 0 篇合格笔记；
- 部分成功：至少一个关键词完成，但存在关键词、详情、素材或飞书部分异常；
- 失败：任务配置无效，或所有关键词均未完成。

任务表模式使用已有记录的 `record_id`，任务 ID 为空时生成并回写；不得创建重复任务记录。

## 11. 请求计数

每个关键词的实际 TikHub 请求数为：

```text
搜索分页请求
+ 通过搜索 Gate 的详情请求
```

搜索一次返回多条卡片；卡片条数不是请求次数。图片和视频下载走素材 URL，不计入 TikHub 请求数。多关键词模式同时输出每个关键词增量和任务累计值。

TikHub 请求不自动重试。用户已明确下达执行动作时，先告知关键词、每词卡片数和成本边界后直接执行；只有范围或成本不明确时才询问。

## 12. 本地输出

```text
projects/03小红书/01小红书素材/<关键词>/
├── 01笔记详情/<关键词>.md
└── 03笔记素材/<Note ID>/
```

每个关键词只保存一份聚合详情 Markdown，不生成评论文件，不保存搜索结果 JSON。

## 13. 飞书字段

采集任务：

```text
任务ID、搜索关键词、排序依据、笔记类型、发布时间、采集数量、
最低点赞数、最低收藏数、最低评论数、采集状态
```

笔记详情：

```text
Note ID、作者昵称、用户ID、标题、正文、话题、点赞、收藏、评论、
转发、原文链接、来源关键词、首次任务ID
```

评论表（预留，本版本不写入）：

```text
评论ID、NOTE ID、用户ID、评论内容、点赞、用户昵称
```

## 14. 验收标准

- 采集数量限制搜索卡片数，不限制合格笔记数；
- 多关键词按 `#` 顺序拆分，数量按每个词计算；
- 搜索卡片完成类型和互动筛选；
- 详情不重复执行时间或互动筛选；
- 未通过搜索 Gate 的卡片不请求详情；
- 同一任务跨关键词重复 Note ID 不重复请求详情；
- 不请求评论接口，不生成本地评论文件，不写飞书评论表；
- 零篇合格但流程完成时状态为成功；
- 任务表模式只领取并更新已有未采集记录；
- 每个关键词和整个任务的请求次数可核对；
- 本地目录和飞书字段严格符合约定。
