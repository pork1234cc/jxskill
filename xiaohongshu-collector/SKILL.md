# 小红书关键词采集

先用搜索卡片完成便宜筛选，再为通过门槛的笔记请求详情和素材。`采集数量`表示每个关键词读取的搜索卡片数，不表示最终必须保存的合格笔记数。当前评论正文采集未接入。

## 运行环境

把当前 `SKILL.md` 所在目录作为 `<SKILL_ROOT>`，并在保存公共 `.env` 的工作区根目录执行命令，使用该工作区 `.venv` 的 Python。下面命令中的 `<SKILL_ROOT>` 需替换为实际绝对路径，不能假定 Skill 安装在 `.agents/skills`。缺少虚拟环境或配置时先报告所缺项。

## 两种能力

### 指定关键词即时采集

用户明确给出关键词时，执行：

```powershell
& .\.venv\Scripts\python.exe "<SKILL_ROOT>/scripts/run_collector.py" collect "<关键词>" --count <采集数量>
```

例如“`小红书采集 AI工具 5篇`”表示读取“AI工具”的前 5 条搜索卡片，按门槛筛选后保存实际符合条件的 0～5 篇。飞书配置完整时，为这次即时采集新建任务记录并同步结果；配置不完整时只保存本地结果。

### 飞书任务表采集

用户说“开始笔记采集”时，直接执行：

```powershell
& .\.venv\Scripts\python.exe "<SKILL_ROOT>/scripts/run_collector.py" tasks
```

读取采集任务表中全部“未采集”记录，按飞书返回顺序串行处理，不创建重复任务。领取任务后更新为“采集中”，完成后更新为“成功”“部分成功”或“失败”。

## 任务与筛选规则

- “搜索关键词”允许用半角 `#` 分隔多个词；清理空词并按首次出现顺序去重，然后逐词采集。
- “采集数量”按每个关键词分别计算。两个关键词、采集数量 40，最多读取 80 条搜索卡片。
- 发布时间只使用“不限、一天内、一周内、半年内”，直接传给搜索接口，不在详情阶段重新判断。
- 笔记类型只使用“不限、视频、图文”；排序只使用“综合、最新、最多点赞、最多评论、最多收藏”。
- 点赞、收藏、评论门槛固定使用 `ALL` 判断；大于 0 的字段参与筛选，`0` 或空值不参与。
- 互动指标和类型只在搜索卡片判断。启用的字段缺失或未达标时直接跳过，不请求详情。
- 详情只补充正文、作者、话题、原文链接和素材地址，不重复执行互动量或时间复筛。
- 评论数仍可作为搜索卡片筛选门槛，但不请求评论接口、不保存评论正文，也不写飞书评论表。
- 同一飞书任务的不同关键词命中相同 Note ID 时，任务范围内复用首次详情，不重复请求；飞书合并“来源关键词”。
- 达到搜索卡片数量后立即停止，不为了凑够合格笔记继续翻页。零篇符合条件但流程完整结束仍属于成功。
- TikHub 请求不自动重试。用户已明确下达采集动作时，先告知关键词、每词搜索卡片数和成本边界后直接执行，不再二次确认；范围或成本不明确时再询问。

## 本地输出

```text
projects/03小红书/01小红书素材/<关键词>/
├── 01笔记详情/<关键词>.md
└── 03笔记素材/<Note ID>/
```

每个关键词保存一份聚合详情 Markdown。图文笔记下载图片，视频笔记下载视频；不生成评论文件，不保存原始搜索结果 JSON。

## 飞书字段

配置好 `NOTE_TOKEN`、`NOTE_WORK`、`NOTE_CONTENT` 及飞书应用凭据后，两个采集入口都会在采集前自动补齐任务表和笔记详情表的缺失字段。数据表本身需提前创建；空任务表也会完成初始化。只新增缺失字段并为新单选字段设置规定选项，保留已有字段和数据，不初始化评论表。

已有字段类型不符、已有单选字段缺少规定选项，或字段接口请求失败时停止，不继续请求 TikHub。按错误提示调整后重新运行即可补齐剩余字段；完整类型及权限要求见 [配置说明](references/configuration.md#首次自动创建字段)。

严格使用以下字段，未经用户确认不得增加、删除、合并或拆分：

- 采集任务：任务ID、搜索关键词、排序依据、笔记类型、发布时间、采集数量、最低点赞数、最低收藏数、最低评论数、采集状态。
- 笔记详情：Note ID、作者昵称、用户ID、标题、正文、话题、点赞、收藏、评论、转发、原文链接、来源关键词、首次任务ID。
- 评论表字段保留供以后接入，本版本不写入评论表。

完整规则见 [references/collection-spec.md](references/collection-spec.md)。首次配置或排查凭据时读取 [references/configuration.md](references/configuration.md)。飞书写入失败时使用已保存的本地结果排查，不重新请求 TikHub。
